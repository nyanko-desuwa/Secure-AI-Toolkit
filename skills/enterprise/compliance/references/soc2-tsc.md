| Series | Name | Technical control examples |

| CC1 | Control environment | Governance context; not evidenced by code alone |
| CC2 | Communication and Information | Control ownership and reporting channels |
| CC3 | Risk Assessment | Risk inputs and assessed changes |
| CC4 | Monitoring Controls | Control operation monitoring |
| CC5 | Control Activities | Enforced policies and procedures |
| CC6 | Logical and Physical Access Controls | Authorization, identity, credential rotation |
| CC7 | System Operations | Logging, monitoring, vulnerability handling |

## Deliberate omissions

No granular identifiers such as CC6.1, CC6.6, CC6.7, CC7.1, CC7.2, CC8.1, or availability
criterion IDs are cited by this skill. Their authoritative wording was not accessible from the
fetched AICPA page. Do not infer them from the series name.

Use series-level mapping only as a navigation aid. The licensed CPA firm's interpretation,
system description, criteria in scope, observation period, and test approach govern the report.
A build artifact may evidence control operation; it cannot create a SOC 2 attestation.
