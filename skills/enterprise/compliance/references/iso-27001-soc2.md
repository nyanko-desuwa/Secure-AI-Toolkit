## Technical-control crosswalk

| Implemented technical control | ISO/IEC 27001:2022 Annex A | SOC 2 series/category |
|---|---|---|
| Append-only audit logging and monitoring | A.8.15 Logging; A.8.16 Monitoring activities; A.5.28 Collection of evidence | CC7 System Operations |
| Server-side authorization and access review | A.5.15 Access control; A.5.18 Access rights; A.8.2 Privileged access rights; A.8.3 Information access restriction | CC6 Logical and Physical Access Controls |
| Storage and transport encryption | A.8.24 Use of cryptography | CC6; Confidentiality where included |
| Credential rotation and secure authentication | A.5.17 Authentication information; A.8.5 Secure authentication | CC6 |
| Blocking, attributable deployment changes | A.8.32 Change management | CC8 Change Management |
| Vulnerability scans, policy gates, tracked remediation | A.8.8 Management of technical vulnerabilities | CC7 System Operations |
| Protected backups and verified restoration | A.8.13 Information backup | Availability where included |

The crosswalk is directional: implementation and operating evidence first, framework mapping
second. Similar titles do not make controls equivalent. Record population, environment, period,
exceptions, and evidence gaps for every row.

## Boundaries

ISO/IEC 27001 certification covers an information security management system and its declared
scope. A SOC 2 report is an attestation for a described system and period. Code, CI artifacts, or
this crosswalk cannot grant either outcome.

ISO titles here were fetched from a secondary catalogue because the normative ISO catalogue was
not accessible. Confirm against a licensed copy. Granular SOC 2 criterion IDs were not available
from the fetched publisher page and are deliberately omitted.
