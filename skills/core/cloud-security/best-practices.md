# Cloud Security Best Practices

Every pattern names its standard. Terraform is real provider syntax, but sample IDs and names
are placeholders. Apply only the fixed blocks.

## IAM least privilege

`A01:2025` · ASVS V8, V13 · CWE-269, CWE-284

Any logged-in deployer with `Action: "*"` can change its own trust policy, pass an admin role to
Lambda, or create keys. A role name such as `read-only` does not constrain a policy.

```hcl
# Vulnerable: the function can administer every service and resource.
data "aws_iam_policy_document" "function_vulnerable" {
  statement {
    effect    = "Allow"
    actions   = ["*"]
    resources = ["*"]
  }
}
```

```hcl
# Fixed: the function can read only its own prefix and publish one metric namespace.
data "aws_iam_policy_document" "function_fixed" {
  statement {
    effect    = "Allow"
    actions   = ["s3:GetObject"]
    resources = ["arn:aws:s3:::example-private-data/exports/*"]
  }

  statement {
    effect    = "Allow"
    actions   = ["cloudwatch:PutMetricData"]
    resources = ["*"]
    condition {
      test     = "StringEquals"
      variable = "cloudwatch:namespace"
      values   = ["Example/Exports"]
    }
  }
}
```

CloudWatch metric APIs require `Resource: "*"`; the condition limits the namespace. The
wildcard is therefore explicit and narrow rather than a default. Use a permission boundary on
roles a team can create and an SCP to deny account-wide escape actions. Azure uses custom role
definitions plus management-group Azure Policy; GCP uses custom roles, deny policies, and
organisation constraints.

## PassRole and role assumption

`A01:2025` · ASVS V8 · CWE-266

```hcl
# Vulnerable: CI can pass any role to Lambda, including an administrator role.
data "aws_iam_policy_document" "ci_vulnerable" {
  statement {
    actions   = ["iam:PassRole"]
    resources = ["*"]
  }
}
```

```hcl
# Fixed: only the named execution role can be passed to Lambda.
data "aws_iam_policy_document" "ci_fixed" {
  statement {
    actions   = ["iam:PassRole"]
    resources = ["arn:aws:iam::111122223333:role/example-lambda-exec"]
    condition {
      test     = "StringEquals"
      variable = "iam:PassedToService"
      values   = ["lambda.amazonaws.com"]
    }
  }
}
```

`iam:PassRole` is not data access; it is authority delegation. Pairing it with a create or
update API turns it into code execution as the passed role. GCP's `iam.serviceAccounts.actAs`
and Azure's `Microsoft.Authorization/roleAssignments/write` deserve the same review.

For cross-account vendors, require an external ID generated by the vendor:

```hcl
data "aws_iam_policy_document" "vendor_trust" {
  statement {
    actions = ["sts:AssumeRole"]
    principals {
      type        = "AWS"
      identifiers = ["arn:aws:iam::444455556666:root"]
    }
    condition {
      test     = "StringEquals"
      variable = "sts:ExternalId"
      values   = ["vendor-generated-customer-value"]
    }
  }
}
```

The external ID prevents the vendor from confusing one customer with another. It is not a
password. For an AWS service, prefer `aws:SourceAccount` and `aws:SourceArn` conditions.

## Workload identity

`A01:2025`, `A02:2025` · ASVS V8, V13 · CWE-798

```hcl
# Vulnerable: an EKS pod receives a static access key through a Kubernetes secret.
resource "kubernetes_secret" "aws_key" {
  metadata { name = "example-aws-key" }
  data = {
    AWS_ACCESS_KEY_ID     = "placeholder-id"
    AWS_SECRET_ACCESS_KEY = "placeholder-secret"
  }
}
```

```hcl
# Fixed: IRSA maps this service account to a short-lived, scoped role.
resource "aws_iam_role" "orders" {
  name               = "example-orders"
  assume_role_policy = data.aws_iam_policy_document.orders_trust.json
}

resource "kubernetes_service_account" "orders" {
  metadata {
    name      = "orders"
    namespace = "example"
    annotations = {
      "eks.amazonaws.com/role-arn" = aws_iam_role.orders.arn
    }
  }
}
```

The trust document must constrain the OIDC `sub` to `system:serviceaccount:example:orders` and
`aud` to `sts.amazonaws.com`. EKS Pod Identity is an alternative. GKE uses Workload Identity
Federation and Azure uses Entra Workload ID or a managed identity. The goal is no credential
material in the pod, image, or repository.

## Object storage: block public access and scope URLs

`A01:2025`, `A02:2025` · ASVS V13, V14 · CWE-732

```hcl
# Vulnerable: anonymous reads are allowed by the bucket policy.
resource "aws_s3_bucket_policy" "public" {
  bucket = aws_s3_bucket.data.id
  policy = jsonencode({
    Version = "2012-10-17"
    Statement = [{
      Effect = "Allow", Principal = "*", Action = "s3:GetObject"
      Resource = "${aws_s3_bucket.data.arn}/*"
    }]
  })
}
```

```hcl
# Fixed: public access is blocked, ACLs are disabled, encryption and versioning are on.
resource "aws_s3_bucket_public_access_block" "data" {
  bucket                  = aws_s3_bucket.data.id
  block_public_acls       = true
  block_public_policy     = true
  ignore_public_acls      = true
  restrict_public_buckets = true
}

resource "aws_s3_bucket_ownership_controls" "data" {
  bucket = aws_s3_bucket.data.id
  rule { object_ownership = "BucketOwnerEnforced" }
}

resource "aws_s3_bucket_versioning" "data" {
  bucket = aws_s3_bucket.data.id
  versioning_configuration { status = "Enabled" }
}

resource "aws_s3_bucket_server_side_encryption_configuration" "data" {
  bucket = aws_s3_bucket.data.id
  rule {
    apply_server_side_encryption_by_default {
      sse_algorithm = "aws:kms"
      kms_master_key_id = aws_kms_key.data.arn
    }
  }
}
```

Remove the public bucket policy rather than relying on a second deny. Public-access blocking
stops accidental policy and ACL grants; it does not correct a private principal with too much
access. Azure uses `allowBlobPublicAccess = false`, RBAC, and container settings. GCP uses
public access prevention and uniform bucket-level access.

Presigned URLs, SAS tokens, and signed URLs are bearer capabilities. Bind them to one object and
method, use a short expiry, and never log them. Versioning helps recover from overwrites; Object
Lock, immutable blob policies, or retention locks are needed when the attacker can delete
versions.

## Network: ingress and egress

`A02:2025`, `A06:2025` · ASVS V13 · CWE-284, CWE-668

```hcl
# Vulnerable: SSH is reachable from everywhere and all egress is allowed.
resource "aws_security_group_rule" "ssh_public" {
  type              = "ingress"
  security_group_id = aws_security_group.app.id
  protocol          = "tcp"
  from_port         = 22
  to_port           = 22
  cidr_blocks       = ["0.0.0.0/0"]
}

resource "aws_security_group_rule" "egress_anywhere" {
  type              = "egress"
  security_group_id = aws_security_group.app.id
  protocol          = "-1"
  from_port         = 0
  to_port           = 0
  cidr_blocks       = ["0.0.0.0/0"]
}
```

```hcl
# Fixed: application traffic is from the load balancer; egress goes to a named proxy.
resource "aws_security_group_rule" "app_from_lb" {
  type                     = "ingress"
  security_group_id        = aws_security_group.app.id
  protocol                 = "tcp"
  from_port                = 8080
  to_port                  = 8080
  source_security_group_id = aws_security_group.lb.id
}

resource "aws_security_group_rule" "https_to_proxy" {
  type              = "egress"
  security_group_id = aws_security_group.app.id
  protocol          = "tcp"
  from_port         = 443
  to_port           = 443
  cidr_blocks       = ["10.20.0.10/32"]
}
```

Security groups are stateful; NACLs are stateless. Azure NSGs and GCP firewall rules have
provider-specific evaluation and targeting. None replaces application authorization. Restrict
egress because it is the exfiltration path people forget. Use private endpoints for managed
services. A VPC is routing and isolation, not proof that a resource is private.

## Metadata service and SSRF

`A01:2025`, `A02:2025`, `A06:2025` · ASVS V2, V13 · CWE-918

```hcl
# Vulnerable: IMDSv1 is available and a two-hop response can reach a pod network.
resource "aws_instance" "app" {
  ami           = "ami-example"
  instance_type = "t3.micro"
  metadata_options {
    http_endpoint = "enabled"
    http_tokens   = "optional"
    http_put_response_hop_limit = 2
  }
}
```

```hcl
# Fixed: require IMDSv2 and keep the response on the instance where possible.
resource "aws_instance" "app" {
  ami           = "ami-example"
  instance_type = "t3.micro"
  metadata_options {
    http_endpoint               = "enabled"
    http_tokens                 = "required"
    http_put_response_hop_limit = 1
  }
}
```

IMDSv1 turns a URL-fetch SSRF into credentials. IMDSv2 requires a PUT token and a header; hop
limit 1 helps stop forwarding from containers. Fix the SSRF too: allowlist scheme and hosts,
resolve and reject private/link-local ranges, disable redirects, set a timeout, and use an
egress proxy to close DNS rebinding. Azure requires `Metadata: true`; GCP requires
`Metadata-Flavor: Google`. Headers are defence in depth, not input validation.

## Encryption, keys, and TLS

`A04:2025` · ASVS V11, V12, V14 · CWE-311, CWE-319

```hcl
# Vulnerable: a public, unencrypted database with no network restriction.
resource "aws_db_instance" "orders" {
  identifier             = "example-orders"
  engine                 = "postgres"
  instance_class         = "db.t3.micro"
  allocated_storage      = 20
  publicly_accessible    = true
  storage_encrypted      = false
  skip_final_snapshot    = true
}
```

```hcl
# Fixed: private placement, encryption, backups, and deletion recovery.
resource "aws_db_instance" "orders" {
  identifier              = "example-orders"
  engine                  = "postgres"
  instance_class          = "db.t3.micro"
  allocated_storage       = 20
  publicly_accessible     = false
  storage_encrypted       = true
  kms_key_id              = aws_kms_key.database.arn
  backup_retention_period = 7
  deletion_protection     = true
  skip_final_snapshot     = false
  db_subnet_group_name    = aws_db_subnet_group.private.name
  vpc_security_group_ids  = [aws_security_group.database.id]
}
```

Encryption at rest limits disclosure from stolen media and snapshots; it does not stop an
authorised identity. Customer-managed keys support separation, audit, rotation, and cross-
account control. Envelope encryption uses a data-encryption key wrapped by a key-encryption
key. Terminate TLS where you can enforce identity and inspect required traffic, then re-encrypt
on untrusted internal hops.

## Logging and detection

`A09:2025` · ASVS V16 · CWE-778

```hcl
# Vulnerable: trail is single-region, validation is off, and logs land in the workload bucket.
resource "aws_cloudtrail" "audit" {
  name                          = "example-audit"
  s3_bucket_name                = aws_s3_bucket.workload_logs.id
  is_multi_region_trail         = false
  enable_log_file_validation    = false
  include_global_service_events = false
}
```

```hcl
# Fixed: organisation-wide coverage and tamper-evident validation.
resource "aws_cloudtrail" "audit" {
  name                          = "example-org-audit"
  s3_bucket_name                = aws_s3_bucket.security_archive.id
  is_multi_region_trail         = true
  enable_log_file_validation    = true
  include_global_service_events = true
  is_organization_trail         = true
}
```

The archive account must deny workload principals from deleting or rewriting logs. Configure
Azure diagnostic settings to a separate immutable destination and GCP organisation sinks to a
locked bucket. Detection rules worth having cover root use, MFA and key changes, policy and
logging changes, public storage, unusual role assumption or service-account impersonation,
new regions, metadata access, and mass object deletion. Log actor, action, target, outcome, time,
and source — never the credential.

## Secrets, serverless, and Terraform state

`A02:2025`, `A04:2025`, `A08:2025` · ASVS V13, V14 · CWE-312, CWE-798

```hcl
# Vulnerable: value is in state and the function role is oversized.
resource "aws_lambda_function" "worker" {
  function_name = "example-worker"
  role          = aws_iam_role.admin.arn
  environment {
    variables = { DATABASE_PASSWORD = "placeholder-password" }
  }
}
```

```hcl
# Fixed: role is function-specific; code reads a named secret at runtime.
resource "aws_lambda_function" "worker" {
  function_name = "example-worker"
  role          = aws_iam_role.worker.arn
  environment {
    variables = { DATABASE_SECRET_ARN = aws_secretsmanager_secret.database.arn }
  }
}

resource "aws_iam_role_policy" "worker_secret" {
  role = aws_iam_role.worker.id
  policy = jsonencode({
    Version = "2012-10-17"
    Statement = [{
      Effect = "Allow"
      Action = ["secretsmanager:GetSecretValue"]
      Resource = aws_secretsmanager_secret.database.arn
    }]
  })
}
```

The ARN is not a secret, but Terraform state still contains arguments and can contain secret
values returned by data sources. Protect state as sensitive data. Cache a secret during a cold
start only with a bounded lifetime and a refresh strategy. Validate event-source trust and
function invocation separately from the execution role.

## IaC policy and drift

`A01:2025`, `A02:2025`, `A08:2025` · ASVS V13, V15 · CWE-1188

Review the plan as a security review. Reject a plan that creates public endpoints, broad roles,
unencrypted data, unrestricted egress, disabled logging, or a new long-lived key. Run OPA/
Conftest or provider-native policy against `terraform show -json`, then run drift detection.
A clean plan is not proof of a clean account if someone changed the resource outside Terraform.

## Cost as a security signal

`A02:2025`, `A09:2025` · ASVS V13, V16 · CWE-778

Credential compromise often appears first as GPU instances, unfamiliar regions, high-volume
API calls, or storage growth. Alert on budget and anomaly thresholds in every account,
subscription, and project. Correlate cost with CloudTrail, Activity Log, or Audit Logs before
assuming an attack; cost alerts are a signal, not an incident verdict.
