## The ones that land on adapters

### API1 Broken Object Level Authorization

An id arrives through an adapter and a use case fetches it without checking that the actor owns
it. The port signature decides whether that is possible: a method taking only an id has no value
from which ownership can be derived. This is the same finding as `A01:2025` seen from the object
level.

### API3 Broken Object Property Level Authorization

Both directions of adapter mapping. Inbound, reusing a core type as the wire type lets a client
set a field it should not - role, tenant, status, price. Outbound, returning a domain object to
the serializer means every field it gains later is published. The adapter maps an explicit list in
each direction.

### API4 Unrestricted Resource Consumption

The category for most of this skill's cost section: an unbounded queue between an inbound adapter
and the core, an outbound read with no byte cap, a list port with no server-side maximum, an
uncapped retry, a client with no timeout, a pool with no ceiling. Each one is reachable by whoever
can reach the adapter.

### API5 Broken Function Level Authorization

The second-adapter problem in its administrative form. An admin CLI or an internal endpoint calls
the same use case with no actor, or with a synthetic superuser, so an operation intended for one
role becomes reachable through a path nobody reviewed.

### API7 Server Side Request Forgery

The driven port that fetches a user-influenced URL. The core cannot defend this - it has no
concept of an address or a redirect - so the control belongs in the outbound adapter: scheme
allowlist, every resolved address checked against private and link-local ranges, redirects
refused, connect and read timeouts, a byte cap, and schema validation before the response becomes
a domain value. Controls in depth are in `skills/core/api-security/`.

### API10 Unsafe Consumption of APIs

A third-party response trusted because it came from a vendor. The driven port states what the core
accepts; the adapter validates the response against that before constructing a domain object, and
never deserializes with a format that can instantiate arbitrary types.

## Not addressed here

API2 Authentication, API6 Sensitive Business Flows, API8 Misconfiguration, and API9 Inventory are
adapter and operational concerns rather than consequences of the port structure. `skills/core/`
covers them.
