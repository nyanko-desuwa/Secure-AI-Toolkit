# Cryptography Verification Checklist

Run before returning code. Mark each item pass, fail, or not applicable. "Not applicable" needs a
one-line reason — an unexplained skip is a gap.

Only the sections the change touches need running. A password-hashing change does not need the
certificate section.

## Threat Model (A04 · ASVS V11)

- [ ] The attacker this protects against is written down, not implied
- [ ] The key is stored somewhere the attacker in that model cannot reach
- [ ] Consequence of key loss is stated and accepted by someone who can accept it
- [ ] Consequence of key exposure is stated, with the blast radius bounded
- [ ] Application-layer encryption is justified over platform disk or database encryption, or
      dropped in favour of it

## Password and Credential Storage (A07 · ASVS V6, V11 · CWE-916, CWE-759)

- [ ] Argon2id, or scrypt/bcrypt/PBKDF2 with a stated reason
- [ ] Parameters meet or exceed [references/password-storage.md](references/password-storage.md)
- [ ] Cost measured on production-grade hardware, under one second per hash
- [ ] Salt generated by the library, not supplied or derived from the username
- [ ] bcrypt paths cap input at 72 bytes rather than truncating silently
- [ ] Full encoded hash stored, including algorithm and parameters
- [ ] Login path re-hashes when stored parameters are below current policy
- [ ] Verification is constant-time, via the library's `verify`, not a string compare
- [ ] Password never logged, never in an exception message, never in a request dump

## Randomness (ASVS V11 · CWE-338, CWE-330)

- [ ] Every token, session ID, salt, nonce, reset link, and API key comes from a CSPRNG
- [ ] No `Math.random`, `random.random`, `rand()`, `mt_rand`, timestamp, or counter as a secret
- [ ] At least 128 bits of entropy for anything an attacker may guess offline
- [ ] `crypto.randomUUID`/UUIDv4 used only where 122 bits is enough, never UUIDv1
- [ ] No seeding of a PRNG with anything, anywhere, for a security purpose

## Symmetric Encryption (A04 · ASVS V11 · CWE-323, CWE-329, CWE-353)

- [ ] AEAD mode: AES-GCM, AES-CCM, ChaCha20-Poly1305, XChaCha20-Poly1305
- [ ] No ECB. No CBC or CTR without a separate verified MAC, and prefer AEAD over building that
- [ ] Nonce is unique per message under the key, and the uniqueness argument is written down
- [ ] Nonce is not a constant, not zero, not a hash of the plaintext, not reused after a restart
- [ ] Message count per key is bounded, or the nonce is wide enough (192-bit) that it does not matter
- [ ] AAD binds the context that must not be swapped — record ID, tenant, field name, version
- [ ] Algorithm identifier and key ID stored alongside the ciphertext
- [ ] Decryption failure raises. It does not return null, empty, or the ciphertext

## Key Lifecycle (A04 · ASVS V11, V14 · CWE-320, CWE-321, CWE-798)

- [ ] No key literal in source, config committed to git, test fixture, or container image layer
- [ ] Key material comes from a KMS, HSM, or secret manager at runtime
- [ ] Data keys are per-record or per-tenant, wrapped by a KEK — envelope encryption
- [ ] Rotation is possible without re-encrypting every row, and the procedure is written
- [ ] Old key versions retained for decrypt only, with a defined retirement date
- [ ] Revocation path exists and has been exercised at least once outside an incident
- [ ] Access to the key is logged, and the log names the key ID rather than the key
- [ ] Keys derived from other keys use HKDF, not concatenate-and-hash
- [ ] Backups: the ciphertext backup and the key backup are separable and both recoverable

## Transport and Certificates (A02 · ASVS V12 · CWE-295, CWE-297, CWE-319)

- [ ] Certificate verification enabled on every client. No `verify=False`, no
      `InsecureSkipVerify: true`, no all-trusting `TrustManager` or `HostnameVerifier`
- [ ] Hostname checked, not just the chain
- [ ] TLS 1.2 minimum, TLS 1.3 preferred; TLS 1.0 and 1.1 refused
- [ ] Internal service-to-service traffic is TLS too, or the exception is documented
- [ ] Pinning, if used, has a rotation plan and a backup pin — otherwise it is an outage waiting
- [ ] Certificate expiry monitored with alerting before, not after

## Signatures and Tokens (A07, A08 · ASVS V9, V11 · CWE-347, CWE-696)

- [ ] Verification algorithm comes from server config, never from the token header
- [ ] `none` rejected; HS/RS confusion impossible because the algorithm list is pinned
- [ ] Issuer, audience, and expiry validated, not just the signature
- [ ] Signature verified before the payload is parsed or acted on
- [ ] Webhook signatures verified over the raw body, before JSON parsing
- [ ] Key ID (`kid`) resolved against a known key set, never used as a file path or URL
- [ ] Revocation understood: a JWT stays valid until expiry unless server-side state says otherwise

## Comparison and Timing (ASVS V11 · CWE-208)

- [ ] Every secret comparison uses a constant-time function
- [ ] `hmac.compare_digest`, `crypto.timingSafeEqual`, `hmac.Equal`, `MessageDigest.isEqual`
- [ ] No early return on length mismatch before the comparison
- [ ] Authentication responses do not vary in time by whether the user exists

## Encoding, Deterministic Encryption, and Data Handling (A04 · ASVS V14 · CWE-311)

- [ ] Nothing base64, hex, or URL encoded is described or relied on as encryption
- [ ] Deterministic encryption used only where equality search is a stated requirement, with the
      frequency-analysis leak documented
- [ ] Blind index, if present, is HMAC-based with a key, not a plain hash
- [ ] Data classified before the algorithm was chosen — what is sensitive, and why
- [ ] Plaintext not written to logs, traces, metrics labels, error messages, or debug dumps
- [ ] Sensitive plaintext zeroed or scoped tightly where the language allows it

## Agility and Migration

- [ ] Ciphertext carries a version or algorithm tag so a future migration is possible
- [ ] Decrypt path handles more than one version during migration
- [ ] Migration re-encrypts rather than re-labelling: a weak-algorithm record stays weak until
      decrypted and re-encrypted
- [ ] Rollback plan exists for a partially migrated dataset

## Before Returning

- [ ] Negative tests written and run: tampered ciphertext fails, wrong key fails, expired signature
      fails, truncated tag fails
- [ ] Build or compile step run
- [ ] No key, plaintext, or token in test output or fixtures
- [ ] Temporary key files removed
- [ ] Anything unverifiable stated plainly, not implied to be fine
